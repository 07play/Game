# 步骤 ① 选墨色 · 使用说明

> 项目：Draw Flower　/　Unity 2022.3.62f3c1　/　已通过离线编译校验（0 错误 0 警告）

---

## 〇、最快上手（1 步骤）

菜单 **Tools → 古画教学 → 0⃣ 把教学面板放进 SampleScene**　→  看到弹窗说"已经完成"  →  点 Unity 顶部的 ▶ Play  →  5 个墨色按钮就出现了。

> 这一个工具会**自动**做完所有事：打开 SampleScene、把预制体实例化进去、把 InkColorStep 挂在 Palette 上、保存场景。你不要去手动拖。

---

## 一、这一步实现了什么

| 行为 | 效果 |
|---|---|
| 点**错**墨色 | 在**那个按钮**上生成 `no.png`，永久留在按钮上（不会被自动清掉），同一个按钮默认只标一次 |
| 点**对**墨色 | 在按钮上生成 `yes.png`（带一点弹跳和随机小角度旋转） |
| 点对之后 | 停 0.45 秒 → 5 个墨色按钮**从左到右依次淡出** → 淡完自动隐藏，本步骤结束并抛事件 |

`no.png` / `yes.png` 都是**按钮的子物体**，`raycastTarget = false`，所以它们不会挡住按钮本身的点击。

## 三、菜单一览

| 菜单 | 干啥 |
|---|---|
| **0⃣ 把教学面板放进 SampleScene** | 打开 SampleScene → 检查是否已有实例 → 放进 Panel → 给 Palette 挂 InkColorStep + 写按钮引用 + 写默认值 + **自动建 EventSystem（缺了它按钮点了没反应）** → 保存。 |
| **① 墨色步骤 · 配置向导** | 改正确答案、调参数、一键写引用、给出体检报告。 |
| **② 运行完整校验** | 体检，预制体 / 场景 / 图片 一并查一遍。 |
| **③ 修复场景里的墨色步骤（挂脚本+写引用）** | **这一步最常被需要**。如果 Hierarchy 上看得见 TutorialCanvas/Palette/Ink0~4 但点了没反应，**通常是这两件事之一**：Palette 上没挂 InkColorStep、或者场景里没 EventSystem。点这一刀强挂 + 重写引用 + 建 EventSystem + 写正确答案 = Ink3 → 保存。 |
| **④ 把场景诊断打印到 Console** | 把当前场景里一切详细情况（含 EventSystem 在不在）写到 Console，点完复制贴给我都行。 |

## 三点五、按钮点了没反应？99% 是这两件事之一

| 现象 | 原因 | 解药 |
|---|---|---|
| Hierarchy 上 5 个墨色按钮都看得见，但点了啥都不出来 | **场景里没 EventSystem**——Unity UI 必须有 EventSystem + StandaloneInputModule 才会把鼠标点击路由到 Button.onClick | 菜单 ③ 会顺手帮你建好 |
| 错误图/对号不出现 | Resources/UI/yes.png、no.png **没设为 Sprite 导入类型**（这样 Resources.Load<Sprite> 会静默返回 null） | 我已经做了图片导入强制约束（见第六节） |

## 四、参数速查（`InkColorStep` 组件）

| 分组 | 字段 | 说明 |
|---|---|---|
| 墨色按钮 | Ink Buttons | 5 个按钮，从左到右。留空会自动扫描 `Palette` 下的子物体 |
| 正确答案 | Correct Index | 0 = 最左，4 = 最右 |
| 反馈图 | Yes / No Resource Path | 默认 `UI/yes`、`UI/no`（对应 `Assets/Resources/UI/`） |
| | Feedback Size | 反馈图外框尺寸，等比缩放不变形，默认 108×96 |
| | Feedback Offset | 反馈图相对按钮中心的偏移，Vector2，默认 (0,0)。例如想让它盖在按钮右下角就填 (20, -20) |
| | Random Rotation | 随机 ±18°，看起来像随手贴上去的印章 |
| 淡出 | Fade Delay | 点对后停顿，默认 0.45s |
| | Fade Duration | 单个按钮淡出时长，默认 0.7s |
| | Fade Stagger | 相邻按钮错开，默认 0.09s（这就是"依次淡去"的感觉） |
| | Fade All At Once | 勾上=5 个一起淡出 |
| | Deactivate When Done | 淡完隐藏按钮物体 |
| 规则 | Allow Repeat Wrong Click | 同一错误按钮能否重复点、叠多个 no 图，默认关 |

**事件**（可在 Inspector 里直接挂后续逻辑，不用写代码）：

- `onInkClicked(int)` — 任何墨色被点了
- `onWrongAnswer(int)` — 点错（每次都触发，含重复点）
- `onCorrectAnswer(int)` — 点对
- `onFadedOut` — 5 个按钮淡完了
- `onStepCompleted` — 继承自 StepBase，淡完后触发 → **下一步（点拖线稿显图层）从这里接**

## 五、为什么按钮点击是代码里绑的，不是在 Inspector 里连 onClick

我**没有**往预制体里写 5 条 onClick 持久化调用，而是运行到这一步时自动绑。原因：

1. 预制体里写死的 onClick 一旦物体被删/改名，就会留下 `Missing (Mono Script)`，而且不会报错，只会在真机上"点了没反应"；
2. 自动绑是按 **Hierarchy 顺序**取的，你在 Palette 里拖动按钮换位置，索引会自动跟着变；
3. 以后给预制体做 Variant（换一套墨色图）时不会因为事件引用而炸掉。

如果你确实需要 Inspector 里能看见那 5 条 onClick，告诉我，我给向导加一个「写入持久化 onClick」的按钮。

## 六、附带的两条自动化

**1. 图片导入约束（`UISpriteImportEnforcer`）**
`Assets/Resources/UI/` 下所有图，导入时自动强制为：Sprite / Single / 关 Mipmap / Clamp / 开 Alpha Is Transparency / Max Size 1024 / Android ASTC 6x6。
> 为什么需要：美术丢一张新图进来忘了改 Texture Type，`Resources.Load<Sprite>` 会**静默返回 null**，游戏里表现就是"点错了什么都不出现"，要等真机测试才发现。现在导入那一刻就掰正，并且会在控制台告诉你是谁改的、改了哪几项。

**2. 构建前校验（`AncientPaintingBuildValidator`）**
打包前自动跑一遍体检，有错直接 `BuildFailedException` 打断构建，而不是打完包才发现。

也可以手动或 CI 跑：
```bash
Unity.exe -batchmode -quit -projectPath "D:\Project_github\Draw Flower" \
  -executeMethod DrawFlower.EditorTools.AncientPaintingCLI.RunValidationBatch
```
（有错误时以退出码 1 结束，方便 CI 卡住）
